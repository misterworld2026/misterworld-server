기준 후보: `../소공 제출용/그날code분석산출물.pdf`(21쪽), `../소공 제출용/그날code-SE-2026-002(Mr.World)설계산출물.pdf`(39쪽, v1.9, 작성 중). 사용자에게 기준본 확인 요청 중이다. 원문은 `../미스터월드테마투어.pdf`(2쪽). 페이지 번호는 PDF 물리 페이지다.

## 확인 범위

- 원문: 텍스트 확인.
- 분석·설계: 전체 텍스트 추출 및 모든 내장 도면의 원본 이미지 열람. 설계 클래스도는 원본 추출 및 확대 이미지 확인. 도면의 모든 서명·메시지에 대한 대장 수록·구현 일치 대조는 미완료다.
- 설계 p.6 클래스도, 4장 시퀀스도 전체, p.36/38/39 상태도, 분석 시퀀스·유스케이스·액티비티도는 원본 그림 확인. 그림/본문 차이는 NAME_REGISTER에 별도 기록.
- 요청된 MDJ 5개는 상위 `설계산출물 교류도`에서 발견하여 JSON 파싱과 객체명·메시지 추출 완료. PDF 명칭 대체 근거로 사용하지 않는다.
- HTML, 실제 DDL, API 이미지: 현재 프로젝트 및 상위 소공 폴더에서 미발견. 사용자가 프롬프트에 제공한 API·컬럼 목록은 별도 근거로 사용한다.
- 기존 코드는 진입점, SecurityConfig, SwaggerConfig, contextLoads 테스트뿐이다. Java 21, Spring Boot 4.1.1, Gradle 9.7.1, MySQL 커넥터 사용. 실제 MySQL 서버 버전·기존 데이터는 미확인.

## 확정 규칙

- 허니문·효도 클래식 상품 및 클래식 옵션 금지: 설계 p.9·18, 분석 p.15.
- 완료 2회 이상 다음 신청 10% 할인: 분석 p.4, 설계 p.9·23. 예약·결제 횟수로 대체 금지.
- 완료 이력은 COMPLETED_SCHEDULE + CONFIRMED, 동일 회원·일정 1회: 설계 p.12·28·37.
- 재고는 정수 0 이상. PDF 분석 p.16은 4 이하 부족이지만, 2026-11-03 사용자 결정이 우선하여 **3 이하 부족**으로 변경. 0 OUT_OF_STOCK, 1~3 LOW_STOCK, 4 이상 NORMAL. 부족이어도 저장 허용.
- 고객은 본인 PENDING 신청만 출발 확정 전 취소: 설계 p.9·38.
- 신청 기록은 삭제하지 않음, 진행·완료 일정 취소 금지: 설계 p.37.
- 문자 실패는 업무 롤백 없음, FAILED 하루 1회 재시도, 확정 후 추가 신청은 신규 신청만: 설계 p.10·27·39.
- 음성 미언급은 실패가 아님, 2개 이상 실패 시 재입력, 결과만으로 신청 생성 금지: 설계 p.21·22.

## 추가 설계 원칙

추가 이름은 PDF 명칭 대체가 아닌 구현 지원 요소로 기록한다. 금액·정원·취소 관련 미결정 정책은 기본값으로 확정하지 않는다. 해당 기능은 결정 전 쓰기 처리를 차단하고, 독립적인 기능은 구현한다. 기존 DDL을 받기 전 신규 빈 DB 스키마와 기존 DB 마이그레이션은 구분한다. 기존 DB에 자동 baseline·drop·재생성을 하지 않는다.

공식 호환성 참고: https://springdoc.org/index.html (Boot 4는 springdoc 3.x), https://docs.spring.io/spring-boot/system-requirements.html . Java·Boot 버전은 기존 값을 유지한다.


## MDJ 검토 결과

- `4.9_Inventory_Management_final.mdj`: 등록→수량검증→상태결정→저장, 조회, 수정 3개 분기. `revised`는 목록 선택→수정 중심이다. 부족 수량의 저장을 거부하는 흐름으로 해석하지 않는다.
- A 시퀀스: signup/login, 상품 구성, 음성 해석, 상품 관리. 화면 선택/확인 동작은 저장 API가 아니다.
- B 시퀀스: 일정 선택, 신청, 확정, 알림, 이력, 일정 관리, 현황, 재고 수정. 알림 영속 기록을 커밋 이후에만 만드는 흐름은 장애 시 유실될 수 있어 outbox 보강이 필요하나 현재 미구현이다.
- 교류도 정리본: applyTrip/increaseApplicantCount가 남아 있다. 이 이름으로 PDF의 apply/updateApplicantCount를 대체하지 않았다. PDF 그림에도 본문과 다른 buildScheduleResponse/requestDepartureNotification/savePendingNotification/buildReservationStatusResponse가 있어 문맥별 별도 보존이 필요하다.
- JSON 이름 추출본과 SHA-256은 source-review 폴더에 보관한다. 추출본은 PDF 명칭의 근거를 대체하지 않는다.
